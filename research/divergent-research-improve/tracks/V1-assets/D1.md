- 异质来源：PyPI JSON API（发布历史、requires_dist）＋ GitHub Advisory API（GHSA 数据库）＋ 本机 venv 两库实测；不含任何博客/综述。
- 判别性预测：若"继续用 python-jose"错，则在同一份 DER 公钥 + HS256 伪造 token 上，python-jose 会接受而 PyJWT 会拒绝。
- 完整交付：是（独立给出换/不换的完整答案，不是补材料）。

## 结论
换。触发一票否决：python-jose 3.5.0 对 CVE-2026-85394（critical）**未修**（GHSA 里 first_patched_version = null），本地已复现接受伪造 token。

## 证据卡 1（原文锚点，一手）
- 结论：截至 2026-10-25，python-jose 最高版本 3.5.0 仍在该 CVE 影响范围内且无补丁版本。
- 引文："python-jose through 3.5.0 fails to properly validate asymmetric keys in HMAC initialization, accepting DER-encoded public keys that lack PEM armor or SSH prefixes." / vulnerabilities[0]: {"vulnerable_version_range": "<= 3.5.0", "first_patched_version": null}
- 位置：GHSA-3qf3-8w2g-rqmx，published 2026-09-03，updated 2026-10-05（api.github.com/advisories/GHSA-3qf3-8w2g-rqmx）
- 我原本预期看到什么：以为"3.4.0/3.5.0 已在 2025 恢复发布 → 供应链风险解除"。**它改变了我什么**：恢复发布不等于修完；2025 年两次发版后又在 2026-09 爆出 critical 且无补丁。

## 证据卡 2（实测，可重跑）
- 命令：`python3 -m venv .venv && .venv/bin/pip install python-jose PyJWT && .venv/bin/python probe_p2.py`（输出 probe_p2.out）
- 结果：python-jose 3.5.0 对 DER 公钥冒充 HMAC secret **ACCEPT**（algorithms=['HS256'] 与 None 都接受）；同一输入 PyJWT 2.15.1 在显式 algorithms=['HS256'] 下**也 ACCEPT**，但 PEM 版本两库都 REJECT、PyJWT 未传 algorithms 直接报错。
- 改变了我什么：这不是"哪个库安全"，而是"应用层必须只传 PEM/SPKI 且锁定 algorithms"。原 P2 预测（PyJWT 会拒绝）**方向错**，只有一半成立。

## 证据卡 3（依赖面 / P1）
- python-jose 3.5.0 requires_dist：ecdsa、rsa<5、pyasn1>=0.5（cryptography 只是 extra）；PyJWT 2.15.1：核心零运行时依赖，cryptography 仅 `[crypto]` extra。
- 未施加：P1 的"离线 wheelhouse 删掉 cryptography 与 gcc"这一步没跑（时间），只有元数据，不构成实测。
