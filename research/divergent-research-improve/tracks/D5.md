## 2. 六条改动（机制主张）

核心主张：这套 Skill 现在把“独立性”“多样性”“预算”写成了**声明性要求**（靠 Agent 自觉），所以它们在压力下必然退化成措辞。改动方向是把它们变成**有产物的动作**：一个可判定的入口、一个带等级的降级阶梯、一份可恢复的断点文件、一组不依赖名字的机制字段。文字只是载体，行为改变来自“必须写下/必须标出/必须存在”的产物。

### 3.12 `scripts/check_portfolio.py`：补丁（实测通过，见 §0.5）

1. 在候选循环里，`family = entry.get("mechanism_key")` 那段之后，收集 `moves`/`new_information` 指纹（`moves` 必须是非空字符串数组，`new_information` 必填），存入 `fingerprint_groups`；同时把 `evidence[].source_id` 记入 `used_sources`，缺 `where` 给提醒。
2. `result == "pass"` 时：`criterion` 缺失 → 错误；`artifact` 若既非 `http(s)://` 又不存在于文件系统 → 收入 `artifact_issues`（默认提醒）。
3. 全部候选处理完后：`checked=true` 但不在 `used_sources` 里的来源 → “核对结果未进入任何结论”；同一指纹、不同 `mechanism_key` → “疑似换名…按指纹应算同一族”。
4. `stats` 增 `fingerprint_families`、`candidates_with_fingerprint`。
5. `main()` 增 `--strict`：把 artifact 问题与“疑似换名/checked 未使用”升级为错误（`exit 2`）；结论行在有提醒时改为“结构检查通过，但仍有 N 条提醒需人工确认”。
6. 需要补 3 个测试（本次**没有写**，只验证了原有 6 个测试在补丁后仍通过）：`pass` 无 `criterion` 报错；artifact 不存在进入 `artifact_issues`；同指纹不同 key 报“疑似换名”。

## 4. 主动放弃的改法

**放弃：在 `portfolio.json` 里做“语义去重”（向量相似度 / 内嵌模型判断两个机制是否相同）。** 理由：(a) 硬约束只允许 Python 标准库、无网络、无第三方包，任何“语义相似度”要不就是假的（实际是字符串相似度，逐字相同的机制换个说法就漏），要不就是引入依赖；(b) 语义判断本来就该由人/复核 Agent 做，脚本只应提供**可判定的**信号。替代方案是 M4 的机制指纹：字段闭集、可事前填写、30 秒人工可复核。代价是填字段要多花时间，且指纹仍可被“三字段全一样却真不同”的候选误判为同族——这属于“宁可归并、让人再解释”的保守方向，可接受。

次选放弃：在 `description` 里塞负面触发词（“不适用于单事实核查/报告分工”）。`name+description` 是**每次会话都常驻**的部分，负面词表会向所有用户收取常驻 token，而三问 gate 只在触发后载入；且负面词表必然误伤“快速核查但同时要多来源”这类任务。

## 5. 代价、副作用与未覆盖

- **代价**：`SKILL.md` +22% 行数（全部在触发后载入，不影响常驻开销）；每次派发多写 3 个指纹字段；`RUN.md` 每次阶段切换写一次（约 8 行）。`quick` 的净成本：多读 3 行 gate + 一张 5 行表，但删掉了“补搜/落盘”的模糊要求，实际更轻；这一条我**没有**用真实模型跑过对照，只有文本层面的论证。
- **副作用**：`--strict` 会让历史 portfolio（artifact 写相对路径且文件已挪走）失败；默认仍是提醒，需在 `portfolio-format.md` 里写明。
- **未覆盖**：中英文/IDE 插件触发只做了文本推理，没有真机验证；`quick` 是否真的能压到 10 分钟未测；L3 密封串行能否显著提高机制多样性，未做对照实验（需要多模型重复采样，超预算）。
- **不确定**：Agent Rot 论文是 `physics.soc-ph`、9 个模型，结论“步数而非上下文长度”我只读了摘要，未核正文与附录，引用强度按“支持方向、不作定量依据”处理。MADBench 是对抗攻击场景，用来类比“首轮互相看结果会传播错误”属于**外推**。

## 6. 自检 S1–S6

- **S1 防退化（≥3 个检查点，各有可观察信号）**：① 指纹撞车 → 脚本输出“疑似换名”，人工 30 秒可判；② `pass` 无判据/artifact 不可解析 → `--strict` 退出码 2；③ `checked=true` 未被引用 → 提醒“核对结果未进入任何结论”；④ 缺 `where` → 提醒“未注明原文位置”；⑤ L3 未标等级或写成“多 Agent 并行” → 走查交付文本即可发现。全部有确定性信号，不依赖模型自评。
- **S2 可执行**：每条都有触发条件（三问为否 / 等级未知 / 阶段切换 / `pass` 且 artifact 空）、动作（写一行理由 / 标 L1–L3 / 更新 RUN.md / 改判据）、产物（`不分路：…` 一行、`sealed:` 头、`RUN.md`、脚本错误行）。无额外工具也可执行（只有 M5 需要 python，且是可选的机读路径）。
- **S3 多样性（非计数判据）**：`moves`/`new_information`/`killed_by` 三元组；第三方按“改了什么、新增什么信息、被什么证伪”逐条核对，不数 Agent 数、不数搜索次数、不看名字。生成期（§1 新条目）与汇总期（§3.2）各用一次，避免只在事后判定。
- **S4 成本**：`SKILL.md` 82→100 行（+22.0%）、3638→4402 字符（+21.0%）、8862→10408 字节（+17.4%），三项均 ≤25%；未新增引用文件（`RUN.md` 模板并入 `portfolio-format.md`，降级协议并入 `agent-contract.md`）；`quick` 只多读 3 行 + 5 行表，并明确删去补搜与落盘。
- **S5 可验证**：脚本断言（§0.5 的 4 条命令与输出，含原有 6 个测试仍通过）；走查样例（用实验 A/B 的两个 JSON 作为反例输入，期望 `--strict` 退出 2）；对照实验建议（同一任务跑 L1 与 L3，比较机制指纹族数与“未被引用来源数”）。
- **S6 保留内核**：完整目标 + 宽泛视角（§1/§2 未改）+ 首轮隔离（只增加等级与写盘顺序，不放松隔离）+ 缺口补搜（档位表的补搜列保留）+ 证据与独立评测（§4 未改，且 artifact 检查收紧）。
