# D4 · 证据链与低成本审计：从执行者与审计者两侧设计

> 首轮独立研究记录。视角：**会走捷径的执行 Agent** × **只有 10 分钟抽检的审计者**。
> 时间盒 20–30 分钟；本轮未修改 skill 目录（原型放在 tmp，见 §6），拟改文本见 §5。

## 0. 方法与限制（先说没做到的）

- **检索受限**：本会话 `web_search` 端点返回 401（API key 无效），无法做关键词版图扫描。只能对已知机构页做定向抓取，抓到 4 个一手页面（§10）。因此「领域版图」判断来自既有知识 + 这 4 页，**存在把热门框架当主线锚定的风险**，未做对抗性核对。
- 一手材料只核到：机构说明页（COS）、论文摘要（Turpin 等）、软件文档（statcheck / CRAN）、规范正文（SLSA v1.0 provenance）。其中 SLSA 一页**未找到**我预期的 "non-falsifiable" 措辞，已按未核实处理。
- 没有做真人或真 Agent 的对照实验；「诚实更省力」是设计论证 + 两个合成样本上的脚本验证，不是实测结论。

## 1. 核心主张：三律 + 一条删除原则

假多路研究的可行条件不是「会说谎」，而是**说谎比干活便宜**。因此改进点不是增加要求，而是改变四种记录的成本结构。

**P0 删除律**：一个字段如果其真值无法用另一份记录交叉验证，删除它，或把它换成残渣。
→ 现 `check_portfolio.py` 里 `sources[].checked` 是一个布尔（第 84–85 行、137–138 行）。它零成本可伪造，且是全套证据链的入口。这类字段不是「弱证据」，是**负资产**：它让没干活的人拿到了和干活的人一样的外观。

**P1 残渣律**：只采信**诚实执行时顺手产生、伪造时必须凭空发明**的材料。
判据一句话：这份材料能不能直接从动作里复制出来？引文能复制自原文；报错能复制自终端；被否掉的搜索结果能复制自返回列表。而「已核实」「原理不同」「已独立验证」不能复制自任何东西——它们只能被发明，因此**必须删掉或降级**。
依据：Turpin 等（2023）证明模型的过程叙述可以「plausible yet misleading」，且在输入被加偏置后**系统性地不提**该偏置（准确率最多降 36%）。自我叙述不是过程证据，这是 P1 的经验基础。

**P2 事前律**：只有「写下时其结果还不可能是已知量」的记录才有证据力。
30 秒判据给审计者用：**「如果这一行是假的，后面哪一行必须跟着变？」**答不出来的行是装饰。这个问题比「这条证据充分吗」便宜一个数量级，且不需要领域知识。
依据：Registered Reports 的做法是**数据收集前**评审、按注册方法执行即临时接受，并明确以此消除选择性报告与发表偏倚（COS 页面原文，见 §10）。要点不是禁止事后叙述，而是让事后叙述**不产生证据地位**。

**P3 一致性律**：审计不查完备，只查矛盾。伪造单个点是廉价的，伪造一组**互相自洽**的记录是昂贵的。
statcheck 是这个形态的成熟先例：从报告的检验统计量与自由度**重算** p 值，不一致即标记（CRAN 文档原文）。它不判断科学对错，只在秒级抓一类特定造假。本设计照抄这个形态：不做语义判断，只做跨记录交叉验证。

三条合起来的效果：伪造者要同时编造 4 份互相自洽的材料（引文与页码、被否掉的搜索、事前预测、顺序日志），而诚实者只需把本来就会产生的 4 份材料留下。

## 2. 候选机制（每条：挡哪种作弊 → 如何发现 → 成本 → 副作用）

| 编号 | 机制 | 挡住的作弊 | 审计者如何发现 | 成本 |
|---|---|---|---|---|
| M1 | 证据卡：`checked` → 逐字引文 + 定位 + 「我原本预期看到什么」 | 未打开原文就写「已核实」；只读摘要就引用正文 | 按 `locator` 打开原文，逐字比对引文。伪造一句不存在的引文几乎必然被抓，30 秒/条 | 诚实者本来就要复制引文；伪造者的成本从 0 变成「必须真读或编得能过逐字比对」 |
| M2 | 判别性准入：提交时必填 `nearest_known` + `discriminator` | 同一机制换名当新路线；常规调参说成原理创新 | 问「这个观察真的能让两者预测不同吗」。同族候选给不出区分观察，1 分钟/对 | 1–2 行；对真不同机制的候选几乎无负担 |
| M3 | 预测先行：实验登记写「若成立看到 X，若不成立看到 Y」，结果引用 `prediction_id` | HARKing：结果出来再编假设 | 查日志顺序：result 是否早于 register；预测是否被结果引用 | 已有「先登记再运行」与假设格式，只加了**双向**预测、判别观察与编号回引 |
| M4 | 顺序账本 `journal.jsonl`（seq 单调追加）+ 机器不变量 | 先看结果再声称独立；汇总后才补登记；把汇总写成「各路独立得出」 | 跑脚本，0 秒；三条不变量：result≥register、synthesis≥全部 submit、peer_read 早于双方 submit 即告警 | 每步一行 JSON |
| M5 | 兄弟泄漏检测（去标题后 ≥20 字逐字重合） | 首轮互相看结果；复制兄弟稿改词 | 跑脚本，秒级，输出重合片段与上下文 | 模板句会误报 → 排除标题行与共同任务书；只作提醒不作错误 |
| M6 | 抽检种子由**审计时**决定 + 「零新机制」为合法交付 | 抽检前临时补证据；为凑数编机制 | 同一条记录两次抽检结果不同；或审计者换种子复核 | 0；但要求交付物明说「本轮无新机制，排除了什么」 |

M1 与 M4 的关系要讲清：M4 **挡不住**整份日志事后重写（见 §7 放弃项），它只把「顺手把叙述理平」这件事从零成本抬到「必须重写整个文件并保持内部一致」。这是刻意的性价比选择，不能宣传成防篡改。

## 3. 哪些记录必须事前——只锁三样

事前要求越多，越会被跳过或补写；补写的事前记录是最坏情况（看起来有事前性，实际没有）。所以只锁三样，其余一律允许事后补，但**必须标注「事后」**：

1. **成功标准与反例**（现有 SKILL.md 第 13 行已有，保留）。
2. **每路的起始视角 + 禁传清单**（现有第 35–39 行已有，补「禁传什么」的可执行表述）。
3. **每个关键实验的预测与判别观察**。现有 experiment-protocol 第 16 行已要求「若 X，则 Y，因为 Z」的假设，但**没要求写出两种结果各自应观察到的量**，也没要求结果回引这条假设的编号——所以事后改假设不留痕。这是缺口。

标注「事后」这个动作本身是关键设计：它不禁止任何写作，只**降权**。禁止会诱导隐瞒，降权不会。

## 4. 让诚实成为最省力路径（四个成本杠杆）

光加检查只会让作弊更精细。必须同时降低诚实成本：

1. **记录有上限**：每路正文 ≤1 页、证据卡 ≤5 张，超出不加分。诚实写满约 15 分钟；伪造一份「看起来完整」的记录反而更久。现 skill 的交付清单有 8 项且无上限，这是造假的第一个动因。
2. **零结果合法**：`verdict: exhausted` + 列出排除了哪些机制。现 skill 第 74 行要求报「多少条真正不同且达到证据门槛的路线」，却没有给「0 条」一个体面的位置。
3. **降级路径有名字**：现第 41 行只有禁令（「不得假称完成多 Agent 研究」），没有合法替代，结果是逼出假称。给一个可命名的模式：**单 Agent 串行多视角（已声明）**，仍走完整流程，只标注独立性未验证。
4. **模板即记录**：派发模板的字段 = 最终交付字段，写一次。研究写一遍、记录再写一遍，重复劳动是造假的第二动因。

你不需要懂这个领域。你只需要让「没干活」比「干活」更贵。**只查矛盾，不查完备**：抽查 2 条比通读 40 页有用。

## 探针 1：引文对不上原文（3 分钟）

1. 打开 portfolio，取 `sources` 中 `checked=true` 的条目，用你自己临时选的种子随机抽 2 条（不要用执行者给的种子）。
2. 按 `locator` 打开原文，逐字比对 `quote`。
3. 判定：一致 / 部分一致（改写、拼接、断章取义）/ 不一致（原文没有这句）/ 打不开。
4. **任一「不一致」即停止其余抽查**，直接判该路证据不可用——这是高基率信号，不需要再找第二个。

## 探针 2：判别性问题（3 分钟）

对每条候选问一句：「在哪个具体输入上，你的 `discriminator` 会让本机制和 `nearest_known` 给出不同预测？」

- 答得出且指向具体输入 → 机制不同，放行。
- 答「原理不一样」「层次不同」→ 判为同一族，要求合并或补观察。
- 两条候选的判别观察相同 → 必是同族。

## 探针 3：机械一致性（2 分钟）

~~~bash
python scripts/audit_run.py --journal journal.jsonl --tracks tracks/ --portfolio portfolio.json --seed <你临时选的数>
~~~

三条硬错误即可判定流程造假：结果早于登记；汇总早于某路交付；某路在对方交付前读过它且自己尚未提交。提醒项（逐字重合、无凭据断言、通过与基线比较却无判别观察）需要人看一眼，不自动定罪。

## 7. 我主动放弃的改法：哈希链防篡改账本

**想法**：`journal.jsonl` 每条带前一条的 sha256，形成哈希链，改动历史即断链。

**放弃原因**：威胁模型不成立。执行者**就是**写记录的人，它可以整链重算或直接重写文件——哈希链只防「手滑」和「顺手改一句」，不防有意造假。要真正防伪必须有外部锚点（宿主或用户侧写入、可信时间戳），这违反「无外部服务依赖」的硬约束，且会把 `quick` 变重。更糟的是它会带来**虚假的安全感**：一个看起来防篡改的日志会让审计者少做探针 1，而那才是真正抓得住人的检查。
取舍：宁可用一个明说自己「只防叙述漂移、不防伪造」的普通日志，配合外部抽查。

（同类放弃：用脚本做语义去重。无嵌入模型即可判「同一机制」不现实；改成让人工回答一个判别性问题，1 分钟/对，比假语义去重便宜且诚实。）

## 8. 失败与未覆盖

1. **语义抄袭未覆盖**：M5 只测逐字重合。看过 D1 再改写，检测不到。我的假设是「改写抄袭的成本已接近独立工作，收益只剩方向锚定」，**未验证**。
2. **引文造假的漏检率未知**：模型可以从摘要或记忆造出「像原文」的句子，逐字比对能抓大部分，但抓不到「摘要级正确、正文级张冠李戴」。未做定量测试。
3. **日志仍可整份重写**（§7）；只有外部锚点能解决，已放弃。
4. **`discriminator` 的质量无法机械判定**：脚本只查「有没有」，不查「好不好」。审计下限明确写进 audit.md 的探针 2，但这一步仍靠人。
5. **样本极小**：2 个合成 fixture + 13 个单测，无真人/真 Agent 对照，无跨任务泛化证据。
6. **未核实**：statcheck 在真实文献中的错误率（PubMed 抓取被 Cookie 拦）；SLSA「non-falsifiable」原文措辞（v1.0 provenance 页正文未出现该词）。
7. **检索缺陷**：`web_search` 不可用，版图扫描未做（§0），这是我这份设计最可能偏的地方。
