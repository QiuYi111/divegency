## 0. 一句话结论

**这个 Skill 的瓶颈不在"发散得不够"，而在两处：(a) 发散的"单位"不是异质的——同一个底座模型换角度，增益在算力对齐后基本消失；(b) 它的"验证"只校验形式——而一手证据里最典型的失败恰恰是"验证全部通过、产物仍然错的"。** 所以最高价值的改动不是加 Agent、加清单条目，而是把"独立性"和"已验证"这两个词从**声明**改成**可出示的产物**。

## 2. 候选机制（为什么这些改动会改变行为）

### M1 增益来自异质性，不来自路数

2502.08788（5 种 MAD × 9 个基准 × 4 个底座模型）结论：MAD **经常打不过 CoT／Self-Consistency 这类单 Agent 基线，即使消耗显著更多推理算力**；同时"模型异质性（model heterogeneity）是普遍有效的解药"。2311.17371 独立复现了前半句：多 Agent 辩论"不能可靠地胜过 self-consistency 与多路径 ensemble"，而且对超参更敏感。

→ 对 Skill 的含义：现在的 `quick/standard/deep = 3/4/6 路` 是**计数式**设计，而计数本身不带信息。如果 6 路都是同一个模型、同一批搜索结果、只是换了措辞的起点，那么按这两篇的证据，预期增益接近零，成本却线性上升。**"路数"必须让位给"可出示的异质来源"**。

### M2 失败集中在"规格"和"验证"，不是"广度"

MAST（1600+ 条带标注轨迹、7 个框架、14 种失败模式、3 大类、人工标注 κ=0.88）给出可引用的分项占比（原文 §4.1，正文我亲自打开 ar5iv 页）：

- 未遵循任务要求 FM-1.1 **10.98%**；步骤重复 FM-1.3 **17.14%**；未识别任务已完成 FM-1.5 **9.82%**；
- 带着错误假设继续而不澄清 FM-2.2 **11.65%**；任务跑偏 FM-2.3 7.15%；
- 过早终止 FM-3.1 **7.82%**；无验证或验证不完整 FM-3.2 **6.82%**；验证错误 FM-3.3 **6.66%**（FC3 合计 21.3%）。
- 干预实验：改进 agent 角色规格使成功率 **+9.4%**；对 ChatDev 的干预 **+15.6%**；即便如此 ChatDev 在 ProgramDev 上正确率只有 **33.33%**。

最关键的一段（§4.1，原文）：ChatDev 生成的国际象棋程序"**通过了所有轮次的验证**，但包含运行时 bug（例如接受非法走子），因为验证者只做了编译通过、注释齐全这类**表层检查**，没有按真实棋规校验"。

这段话和本 Skill 的 `check_portfolio.py` 是**同构**的：脚本对 `pass` 的唯一硬要求是 `artifact` 非空。我在 §5 用一条命令复现了"空壳通过"。

→ 含义：把预算从"再多派一路"挪到"让验证会失败"。

### M3 没有外部反馈的自我复核会退化

2310.01798：在不引入外部反馈时，LLM 的 intrinsic self-correction **会让推理准确率下降**。2306.05685 记录 LLM-as-judge 的位置/长度/自我增强偏差；2404.13076 进一步给出因果链：模型的**自我识别能力与自我偏好强度线性相关**。

→ 含义：现在的"独立审查 Agent 找致命缺陷"如果没有引入任何新东西（新资料、新输入、重跑），在证据上属于 M3 描述的情形，不能算验证；而 Skill 第 4 节只写了"尽量让方案提出者看不到最终测试数据"，没有规定**复核者必须带来新信息**。

### M4 首轮隔离的正当性要换一个理由

2609.04445（"Conformity Breaks Conformal Prediction"）：同一模型单独回答时校准有效的置信证书，在看到同伴**一致地给出错误答案**后失效——不是因为答案变了，而是**打分机制发生了漂移**。2609.33495 补充：从众强度取决于对方 Agent 的"身份"，不只是共识本身。

反方向的证据也在：2609.33936 系统重检了"人工蜂群/开放生成同质化"的三条核心结果并给出反驳（聚类、谱分析、标签都不支持原来的"坍缩成两簇"）；2607.13077 主张 AI 同质化的是**句法而非语义**。

→ 含义：Skill 里"首轮隔离"应当保留，但**理由从"防止同质化"改成"防止评分与判断漂移"**——前者证据有争议，后者有一手实验。"每个人都独立想"不需要靠"LLM 一定趋同"来论证。

### M5 复杂度本身是负债

2407.01489（Agentless）：三阶段固定流程（定位→修复→补丁验证）在 SWE-bench Lite 上以 **32.00%（96 个正确修复）、$0.70** 的代价超过当时所有开源软件 Agent，并顺带指出基准里存在错标与误导性 issue 描述。

→ 含义：新增检查点必须是"少而硬"，不能是"多而软"。任何一条新条款都要能回答"它删掉了什么"，否则就是把 Agentless 的反面教训再犯一次。

## 4. 拟改文本（可直接替换/插入，中文）

### T1 —— `SKILL.md` §"## 2. 真正独立的首轮研究"，在"若宿主不提供真实隔离的子 Agent"段**之前插入**

> **独立性要能出示，不能只靠声称。** 每一路开工时在自己的产物开头写三行（`quick` 模式也只写这三行，不额外建文件）：
>
> - **异质来源**：这一路与其它路**不同的信息来源或推理表述**是什么（不同底座模型／不同资料集／不同的数学或物理表述／不同约束瓶颈）。**同一个模型 + 同一批检索结果 + 只换了措辞的起点，不算新的一路**，不计入路线数。宿主只有一个模型时，照实写"同模型多会话"，并把该路多样性声明降为"仅起点不同"。
> - **判别性预测**：如果这一路是对的、而另一条**具体**路线是错的，那么在同一输入上应观察到的差别是什么（一句话，必须是别人能看见的量或现象）。写不出判别性预测的两条路，按同一路处理。
> - **完整交付**：这一路独立给出完整答案或完整方案。只写某一章节、只补材料、只做批评的，属于报告分工——把它标成 `support`，不计入路线数，也不要在最终报告里算作"独立路线"。
>
> 汇总时的判定信号（第三方可查，不靠模型判断）：两路"关键假设"逐条相同 → 同一路；两路对同一现象给出同向预测、且在任何一路的资料里都找不到分歧点 → 同一路。

*针对*：报告分工冒充独立研究；同机制换名；用 Agent 数冒充多样性（S1、S3）。
*代价*：每路多写 3 行；`quick` 净增约 3 行/路，不新增文件、不新增工具（满足 S4）。

### T2 —— `SKILL.md` §"## 3. 建立方案库，找出遗漏" 第 2 条，**整条替换**

> 2. 比较**为什么有效**，而不是名字、措辞或所属领域。去重不看标签，看"这两条能不能被同一个实验分开"：
>    - 先问：这两条在**什么输入上会给出不同结果**？答不上来的，归为同一族。
>    - 同一族里只保留证据最强的一条做代表，其余记为"变体"，**变体的失败条件仍然保留**（那往往是下一轮的起点）。
>    - `mechanism_key` 由汇总者在看完全部候选**之后**统一命名，**提出者不填**。提出者只写"判别性预测"与"关键假设"；汇总者按这两项聚族，并保证第三方能从候选原文复算出同一个分组。只有当某条候选的判别性预测与所有既有族都不同时，才允许新开一族。
>    - 关键假设不同、失败边界不同的方案分别保留，**即使名字很像**。

*针对*：`mechanism_key` 由提出者事后自命名，事前无法约束（BRIEF §6 的怀疑点，我确认它成立：脚本对 `mechanism_key` 只能做字符串去重）。
*代价*：汇总者工作量略增；提出者反而更省（不用想标签）。

### T3 —— `SKILL.md` §"## 4. 验证，然后选择" 中"**评测必须独立**"那一条，**整条替换**

> - **"已验证"= 一个别人能重跑、并且可能失败的检查。** 三项齐全才能写"已验证"，缺一项只能写"待验证"：
>   1. **可重跑**：命令或操作步骤、输入、版本/环境、原始输出的存放位置。别人照做应得到同样结果。
>   2. **会失败**：至少给出一个"若结论错就会失败"的输入或反例，并说明它为什么能区分对错。**只检查形式**（文件存在、能编译、有引用、字段齐全）**不算验证**——它会在结论错误时照样通过。
>   3. **判定者没参与提出，且带来了新东西**：由未参与该方案的人/会话执行，并至少引入一项提出者没提供过的内容（新打开的原始资料、新输入、重跑结果）。只重读同一批材料写评语，属于无外部反馈的自我复核，按"未验证"处理，写明"未经独立验证，仅有资料支持"。
>
>   另查：只报有利子集、用测试集调参、改指标、硬编码、隐藏运行失败。模型打分只用来分配调查精力，**不用来判定通过**。

*针对*：无独立评测却写"已证明优于基线"；未打开原文就写"已核实"；伪造通过（S1）。
*依据*：E1（验证"全部通过"仍出错）、E4（无外部反馈的自我复核退化）、E5/E6（评审偏差）。
*代价*：增加了"判定者必须带来新东西"的硬门槛——这会让某些任务无法声称已验证。**这是故意的**（S6 允许写"验证强度不足"）。

### T4 —— `references/experiment-protocol.md` §2，在"**先登记，再运行**"那条之后**插入一条**

> - **先写死预言，再运行。** 登记时写下三行："若假设成立，指标应落在 ___；若不成立，应落在 ___；两者可区分的最小差值 ___"。运行后把实测值与预言**并排**保留，**不得回改预言**。预言与实测不符却仍宣称支持假设的，必须给出新的、可再检验的解释，并标注"事后解释"。

*针对*：看完结果再编解释（post-hoc rationalization），这是"常规调参说成原理创新"的常见伴生行为。
*依据*：E1 的干预实验设计（先定义失败模式再干预、再测）；E4 说明事后自评不可靠。
*代价*：一次实验多写 3 行。

### T5 —— `references/methods.md` 末段（"本 Skill 的核心选择…"）**之前插入**

> **证据边界（2026-10 复核）**：多 Agent 辩论类方法在算力对齐后**经常不优于** self-consistency 等单 Agent 基线（arXiv:2311.17371、2502.08788），而**模型/来源的异质性是稳定有效的因素**；多 Agent 系统的失败大量集中在规格与验证两类，典型形态是"所有验证轮次都通过、产物仍然错"（MAST，arXiv:2503.13657）。因此本 Skill 不把"多派 Agent"当作收益来源，只把**异质的起点 + 会失败的验证**当作收益来源。另：'LLM 输出同质化'的证据目前有争议（对照 arXiv:2609.33936），本 Skill 保留首轮隔离的理由是**防止判断因看到同伴结论而漂移**（arXiv:2609.04445），不是"防止模型趋同"。

*针对*：Skill 的隐含预期"多路 → 更好"，以及把隔离建立在有争议的同质化论证上。
*代价*：methods.md 增加约 5 行；无运行时成本。

**这就是 MAST 那个"通过所有验证但接受非法走子"的棋类程序的翻版**：统计口径把这一路记成"有已核实一手证据（1）"且"声称通过测试（1）"。脚本本身在 docstring 里声明不保证真实性，这是诚实的；但它把**未核实的声明计入了正向统计**，读者只会看 `families_with_checked_primary_evidence`。

## 6. 我推翻的直觉 / 主动放弃的一条改法

**被推翻的直觉**："多派几路独立 Agent 就能扩大搜索空间，所以把预算花在路数上是对的。"

证据链：E2 + E3 显示同模型多路在算力对齐后常常**不优于**单 Agent 的 self-consistency；E2 还指出异质模型是稳定增益来源。所以"路数"不是收益变量，**"异质来源"才是**。这直接改变了 Skill 的写法：从"派 N 路"改成"每路必须出示异质来源与判别性预测，否则不计入路线数"。

第二个被推翻的直觉："首轮隔离是为了防止 LLM 输出趋同。"E11 反驳了同质化的强版本。隔离该保留，但理由要换成 E7 的"同伴压力使打分机制漂移"。

**主动放弃的改法：强制"不同底座模型"（model heterogeneity mandate）。**
理由：(1) 宿主可能只有一个模型，硬要求会成为无法执行的条款，违反 S2；(2) 更糟的是它会诱导 Agent 谎称用了不同模型——正是 S1 要防的那类伪装；(3) 我不想用一条无法验证的字段换真实性。替代方案是把它降级为**可出示的来源差异**（资料集/表述/约束瓶颈），并强制在只有单模型时写明"同模型多会话，异质性仅来自起点"——可查、可证伪、不依赖宿主能力。

另外放弃：用标准库 `difflib` 做机制相似度检测。字面相似度与机制相同几乎不相关（"约束求解" vs "从几何反推"字面差异大而机制同），它会生成一个"脚本通过"的假信号——正是 E1 里那个只做表层检查的验证器。改用"判别性预测"这类需人工/第三方复核但可证伪的判据。

## 8. 自检 S1–S6

**S1 防退化（≥3 个检查点，各带可观察信号）**
- 报告分工 → T1 第三行"完整交付" + 标记 `support` 不计入路线数。信号：该路产物缺少完整方案/结论，或只有章节标题。
- 同机制换名 → T2"能否被同一个实验分开"+ T1"关键假设逐条相同"。信号：两条候选在汇总表里"判别性预测"一栏为同一句，或缺失。
- 首轮互看 → 现有条款保留；T3 第 3 项把"判定者带来新东西"设为门槛。信号：复核者报告里没有任何提出者未提供的来源/输入/重跑输出。
- 用 Agent 数当多样性 → T1 明确"同模型+同资料+换措辞不计入路线数"；T2 汇总者事后命名。
- 未打开原文就写"已核实" → T6 第 1 项：无 `where` 不计入 `families_with_checked_primary_evidence`。信号：脚本统计从 1 变 0（§5.3 已复现）。
- 常规调参当原理创新 → T4 预言登记 + 现有"常规优化 vs 原理改变"条款。
- 无独立评测写"已证明优于基线" → T3 三项门槛；缺项只能写"待验证"。
- 伪造通过 → T6 第 2 项 `rerun` + `falsifiers`；信号：`pass` 但无重跑命令/无反例时出现 warning。

**S2 可执行**：每条都是"触发条件 + 动作 + 产物"。T1 触发=每路开工，产物=3 行；T3 触发=要写"已验证"，产物=命令+反例+新引入项；T4 触发=要跑实验，产物=3 行预言；T6 触发=运行脚本，产物=warning。全部零额外工具。

**S3 多样性（非计数，第三方可复核）**：核心判据是"判别性预测"——两条路必须对同一输入给出可区分的观察结果。它不数 Agent、不数搜索次数、不需要 embedding，第三方拿两条候选原文即可复核（能/不能指出分歧输入）。辅以"关键假设集合是否逐条相同"。

**S4 成本**：`quick` 净增约每条路线 3 行文本；不新增文件；`SKILL.md` 改动为 T1 插入约 10 行、T2 替换约 8 行、T3 替换约 11 行，净增约 20 行 / 8.8KB ≈ +8%（含删掉的旧句），低于 25% 上限。新增引用文件：无。

**S5 可验证**：T6 有脚本断言（§5.3 已跑，9 tests OK）。T1/T2 用走查样例：拿任意一份历史首轮产物，填"异质来源/判别性预测/是否完整"三栏，若某路三栏都空则判为不计入——第三方 5 分钟内可做。T3 用审计清单：随机抽 3 条"已验证"结论，检查是否有命令、反例、以及提出者未提供的输入。T4 看实验登记表是否有"预言"行且未被回改。生效时观察到的现象：报告中的"路线数"下降、"待验证"标签变多、脚本 warning 变多而 error 不变。

**S6 保留内核**：同一完整目标（T1 第三行）、宽泛视角（未改动 §1）、首轮隔离（保留，理由更新）、缺口补搜（未改动）、证据与独立评测（T3 强化）。
