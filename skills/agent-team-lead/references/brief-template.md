# 任务说明模板

按工作类型选一份，替换尖括号。路径一律写绝对路径。

## 赛跑

```markdown
你是 <项目> 的设计赛跑者，任务：<要补的东西>。你和另外 <N> 名赛跑者各持一种立场，产出**设计 + 可运行原型**，由决策者亲手体验后挑选。

## 你的立场：<一句话立场>
<这条立场换掉了什么：权威表示 / 求解路线 / 中心视图……；样例数据用什么>

## 必读（只读）
- 需求：<路径>
- 已有决定：<路径>（尤其 <最相关的几条>）
- 相关设计与公共对象模型：<路径>
- 考题：<路径>
- 格式范例：<一个设计节点的路径>、<一份考题的路径>
- 前人产物：<路径>

## 硬约束
1. 每个设计元素都要对应需求或明显的体验改善；没有动机的不做。
2. 成熟实现优先，写明库名、版本、许可证；只有确实不适用时才自研并写理由。
3. 复用已有机制：<列出：对象身份、选择即引用、违例模型、证据绑定修订……>；不另造平行体系。
4. 会进接口的内容给出实体 / 字段 / 枚举 / 接口的 schema 草案。

## 交付（写在当前目录）
1. `DESIGN.md`（以 `# ` 开头）：立场；对象与 schema；接口；每个元素一行对应需求；放弃的方案与理由；开放问题。
2. 原型：在当前目录上用真实或开源样例实现最关键的交互，截图到 `shots/`。
3. `T-ADD.md`：10–15 张场景卡 + 不变量。
4. `REPORT.md`（以 `#` 开头）：做了什么、样例来源与许可证、截图清单、**没做到的如实写**。

## 运行
- 本地服务端口在 <范围> 里自选；浏览器调试端口在 <范围> 里自选。
- 依赖和缓存放在当前目录（例如 `UV_CACHE_DIR`）。
- **用完的服务器和浏览器自己关掉。每完成一部分就写盘。**
```

## 起草

```markdown
你是 <项目> 的设计文档起草者，补：<主题>。方向明确，不赛跑；总指挥会逐条核对你的稿子。

## 任务
<要写的实体 / 规则 / 接口；产出的节点文件名>

## 必读 / 硬约束
（同赛跑）

## 交付（写在当前目录）
1. 设计节点 `<文件名>`（格式按范例；状态写 draft；关系用 <链接格式>）。
2. `T-ADD.md`：场景卡与不变量。
3. `REPORT.md`：写了什么、依据哪些节点、留下的开放问题。
只写文档，不改其他目录。边做边写盘。
```

## 筛查

```markdown
你是 <项目> 的盲点筛查员。<背景：刚发现的一个盲点作为例子>。你的任务是从一个指定视角找出**同类盲点**：需求 / 旅程 / 用户预期存在，但设计、考题或原型没有承接，或者承接得很浅。

## 视角：<一个视角>

## 规则
- 每条盲点给出证据：哪个需求或旅程提出了它（编号 + 原文短引），以及在设计、考题、原型里**搜过哪里、没找到**（文件和关键词）。没证据的不报。
- 不提新愿望，只报“已经被要求或明显被预期，却没被承接”的东西。
- 严重度：**接口级**（改对象身份 / 接口 / 数据模型，越晚补越贵）、**设计级**、**体验级**。

## 交付
`GAPS.md`：结论（最严重 3 条）；盲点清单表（编号 | 盲点 | 来源 | 搜过哪里没找到 | 严重度 | 建议怎么补）；搜索记录。
```

## 反思

```markdown
你是 <项目> 的反思小队成员。<参照物> 和我们有大量重叠。你的任务是**用它来反思我们自己**：我们的设计和定位哪里站得住、哪里站不住、哪里该改。

## 视角：<产品定位 / 架构是否过度设计 / 自建还是接入 / 新颖性 / 红队>

## 规则
每个论断都指向参照物的具体文件或行，以及我们的具体节点；不客套，不为任何一方辩护。

## 交付
`REPORT.md`：结论；论点表（论点 | 参照物证据 | 我们的证据 | 意味着什么 | 建议：保持 / 改设计 / 改定位 / 删 / 加）；我们真正的护城河；我们可能在自欺的地方；按优先级最多 7 条建议动作。
```
