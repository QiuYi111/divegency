# 分路研究

目标：在给定预算内找出**更多有依据、原理真正不同、能够检验**的答案或方案。多派 Agent 不产生收益：同质的几路通常不优于一次认真推理。收益来自**异质的起点**与**会失败的验证**。

## 先判断要不要分路

三问，任一为“否”就不启动：直接回答或检索一次，并写一行“不分路：理由”。①交付物是**一个完整答案或方案**，不是若干章节？②问题可能存在多种解释或实现原理，或者恰恰不知道有哪些原理、需要开放探索？③至少有一次可切分的执行（子 Agent、新会话，或能先写盘再换视角的一段时间）？**说不出两种现成方案不是拒绝研究的理由**。

## 先确定任务

1. 把**最终目标原文**、硬约束、资源和禁止事项写成共同任务书。区分 `facts`、`decision`、`design`、`algorithm` 四种用途，可混合，按最终交付物选主模式。**共同任务书只给目标、事实背景、硬约束和成功标准**；主 Agent 怀疑的缺陷、喜欢的方案、预期发现和待验证的猜测单独封存，不派发给首轮。此规则也约束自我改进 Skill 的任务。
2. **看到候选前**只锁三样：什么算成功、什么条件一票否决、什么证据会推翻结论。只限定结果，不指定实现。其余记录可事后补，但必须标“事后”——事后叙述不产生证据地位。
3. 从原始资料入手：论文正文与附录、代码与测试、标准、官方手册、原始数据、实测或用户提供的文件。二手文章只用于发现线索。派发前用一次轻量检查确认搜索、全文读取、代码与实验工具是否可用，把**可用能力与限制**如实告诉各路，不传具体搜索词和拟定结论。
4. 定档，单位是**独立视角 × 每视角预算**，Agent 个数只是上限：

   | 档位 | 视角 | 每视角 | 补搜 | 落盘 |
   |---|---|---|---|---|
   | `quick` | 2–3 | 1 轮检索 | 不补 | 一个 `RUN.md` |
   | `standard`（默认） | 4 | ≤2 轮 | ≤2 路 | `tracks/`＋可选方案库 |
   | `deep` | 6 | ≤4 轮 | ≤4 路 | 同上＋方案库 |

   视角撞车按一路计，不加派 Agent 凑数。只能串行或用户不要并行时**减视角不减深度**；要并行而宿主做不到时说明限制，不要声称已并行。
5. 改进现有系统、实验或算法前先确认**可重复的基线**与固定衡量方法；没有就说明缺口，不能用无法比较的数字竞选。

## 中途补充信息：先回题，再加派

在 `RUN.md` 保留**目标锚点**：用户最初要达到的结果原话、用于比较方案的成功标准、已确认的硬约束。**目标、衡量指标、手段、风险是不同层级**；允许用户改变目标，但不能因为某个话题刚被提及、刚查到很多资料，就擅自提高它的权重。

收到会影响研究的新消息时，先做一次轻量差异判断，不必每次都写长报告：

1. **定性质**：属于「明确改目标／新增或修改约束／事实背景／候选想法或担忧／局部委托／新工具」哪一类？一条可跨类。用户说“只是举例、随便一提”时，按**候选**而不是指令或偏好排序；用户要求专门回答一项，可完成该局部委托，但不等于更改整个项目目标。重大的目标变更不清楚时，先问一句。
2. **算影响**：记录它具体影响哪些方案、哪条成功标准或一票否决；已有方案排序时，检查是否存在**足以改变可行性或排名**的证据；首轮尚未结束时只记可能的影响，**不得提前选赢家**。若只有假设，给条件结论；若无法说明对原目标的影响，它只是补充材料，不升格为主线。明确的安全／合规禁区先处理，不等抽样。
3. **限扩张**：普通候选或担忧先用最小的检索／一次 `support` 走查；只有发现足以改判的证据，再投入多路。继续做独立探索时，只传必要的**中性事实**，不把新候选、主 Agent 的解释或局部研究任务书发给所有 Agent；声称“反锚定”的路线尤其不能读取带有该暗示的资料。
4. **留痕**：只有改变研究方向、资源或方案排序时，才在 `RUN.md` 简记「原目标 → 新信息及类别 → 影响的候选 → 排名是否改变及依据 → 本次派发范围」。用户明确改目标时，同时记录新旧目标，不得悄悄覆盖原文。

具体派发区别见[独立研究交付要求](references/agent-contract.md)。

## 1. 生成不同的大方向

**先想后搜，但不替研究者预想答案**：先由问题结构写出宽泛起点，再少量检索查漏；比较指标可事前锁定，具体用于区分候选的测试题由各路独立提出，首轮结束后再汇总。主 Agent 自己的测试猜测先封存，不发给研究者。

- **判别问题**：一句“若施加或观察到 X，结果会怎样”，由研究者各自提出并写入自己的记录；首轮后汇总成方案库的公共 `probes`，再让候选在相同问题下给出预测。X 必须真能施加：打乱顺序、删信息、减半预算、换基线、换分布外输入；`facts`／`decision` 用“查哪份资料或哪个对照会分开两种说法”。写不出施加方式的不算。
- 每个视角能**独立解决整个目标**，不是一段报告任务；是一句开放问题，**不能**规定算法、产品、论文或预期结论。
- 视角差异落在机制上：换掉了什么（问题描述／信息来源／约束／目标／搜索空间）、新增什么信息、被什么观测证伪；三条都写不出就是同一个方向。
- 别套用固定人物（研究员／工程师／反对者）；留一名不附带视角、也不收到疑似缺陷清单的 Agent 作对照，`quick` 下至少留一条跨领域或自由探索路线。
- 方向只换说法就重新划分；允许 Agent 发现更有价值的方向后偏离起始视角。
- 覆盖本领域原始研究和其他领域可借用的原理，尤其从任务本身的物理、数学或业务规律出发，不要只在现有工具之间选择。

## 2. 真正独立的首轮研究

优先用宿主原生子 Agent／并行委派。每个 Agent 获得：相同的**中性任务书**（成功标准、硬约束、可用工具，不含主 Agent 的诊断与预设探针）、**仅属于自己的**一个宽泛视角、同一份[独立研究交付要求](references/agent-contract.md)。

**独立性要能出示**。每路产物开头写三行（`quick` 也只写这三行）：**资料与工具来源**（实用过哪些原始资料与工具；同模型多会话如实写，不自称异质）、**可推翻本路的观察**（若核心原理错了，什么具体输入或资料会显示它错；首轮不能要求它预知兄弟路线）、**完整交付**（独立给出完整答案或方案；只写章节、补材料或批评的标 `support`，不计入路线数）。

严禁发送主 Agent 的偏好、其他 Agent 的计划或结论；首轮结束前不互相讨论，也不要规定相同的搜索路线或技术栈。按 Agent 分开保存原始产物（如 `tracks/D1.md`；`quick` 可并入 `RUN.md`，须标 L3 与污染路径）。

**隔离等级与降级**（交付写明等级，L3 不得说成“多 Agent 并行”）：**L1** 原生隔离子 Agent；**L2** 能开独立新会话：每轮只带任务书与该视角；**L3** 单上下文时**密封串行**——一次一路，写完即封存，下一路按“与已封存最不相邻”或抽签选视角，写“顺序模拟，弱于真并行”并列出污染路径。

## 3. 建立方案库，找出遗漏

等首轮都交付后再汇总，不要先选赢家。

1. 提取核心原理、输入、关键假设、适用边界、原始证据、可测结果；事实研究取结论与证据链。
2. 比较**为什么有效**，而不是名字、措辞或领域。把关系分成**已证同原理／已找到区分证据／尚无法区分**三态。换名、同一因果步骤可合并；有可复查的反事实差异才计入“已区分”。几个探针预测相同，只能说**在这些探针上无法区分**，不能推出两套原理相同。缺判别证据的候选留作“待判”，不硬合并，也不算已确认新增机制。`mechanism_key` 只是族标签，不是证据。
3. 区分**常规优化**（调参、换同类工具）与**原理改变**（换问题描述、信息来源、目标或机制）：换掉的是输入或问题描述而非处理方法；说出会推翻哪条既有假设；指出与基线预测相反的输入。三条全否的算常规优化，不占“不同路线”名额。
4. 保留有价值的失败路线及反例，记入 `dead_ends`。**“本轮无新机制”是合法交付**：列出排除了什么、凭什么排除。
5. 四类空白：没人探索的机制、证据缺失、彼此矛盾、验证不足。只在具名空白处补搜：某条判别问题上候选预测一致（需要**更能区分的测试**，不代表原理重复）、全员“未知”（无人区分）、某方向零候选、两条路线结论相反且各有原始证据。补搜派新的宽泛方向，仍须独立解决完整目标；核查争议单派验证 Agent，都不以“润色赢家”为任务。
6. 预算按信息量花、不按当前分数：每个未被反例击中的族至少 1 单元；领先路线累计不超过剩余预算一半；连续两个单元只让领先路线更好，下一个必须用于跨族判别。
7. 收敛**按事件不按钟**：首个候选通过验证、补搜结束、准备写终稿时各做一次四问并写进 `RUN.md`——最近几次动作新增了机制族吗？预算是否全押一族？有没有一路始终无可判定结论？下一个最便宜且能改变结论的动作是什么？宿主有定时能力再叠 60 分钟提醒，没有就按事件触发。

如需可机读方案库，用 [portfolio.json 约定](references/portfolio-format.md)；在 Skill 目录内运行 `python scripts/check_portfolio.py <portfolio.json>`，否则用绝对路径。脚本只检查记录一致性，**不能代替**语义去重和科学判断。

## 4. 验证，然后选择

- 先执行硬约束，再比较效果、成本、复杂度、鲁棒性和风险。维度须与目标相关，不凭加权总分定胜者。先估分辨率：同一基线重复测出波动带，差距小于最小可分辨差异时判并列，不得宣称“最佳”。
- **事实调研**：逐条打开来源、核对引用与时间，主动找反证；标明证实、冲突、暂不可证。“已核实”的一手来源必须留**原文锚点**：逐字引文＋可定位位置（页／节／行／时间戳）＋它支持的具体子结论；写不出锚点只能写“只见到标题或摘要”。
- **方案选型**：查规格、限制、价格与维护；对关键争议做可重复的小试用。
- **工程／算法**：允许时写最小原型；同一输入、预算、指标和反例。保留命令、版本、原始输出与失败记录。高风险但可能改变原理的实验与稳妥的局部改进**分开安排**，不要把预算全用在调参。较贵实验先读[实验与独立评测](references/experiment-protocol.md)。未经允许不改生产系统、不用昂贵资源。
- **“已验证”= 别人能重跑、并且可能失败的检查**，三项齐全才能这么写：①可重跑（命令、输入、版本、原始输出）；②会失败（给出一个若结论错就会失败的输入，并说明为何能区分）；③判定者没参与提出且带来提出者没有的东西（新资料、新输入、重跑）。只重读同批材料写评语按“未验证”处理；只查形式（文件在、能编译、字段全）不算验证。措辞随等级：独立且可重跑→“在保留集上优于基线”；自测→“开发集结果，未独立验证”；无测试→“未验证”。
- 先让独立审查 Agent 找每条路线的致命缺陷，再依据外部证据或实验决定；模型评分只用于分配调查精力。**复核前冻结候选版本**（Git commit，或文件快照与校验值），复核者只读这一版且不给预期漏洞答案。收齐复核后才修改；修改过的版本需用**未见过的新输入**再测，不能只复跑已知错题。详见[独立研究交付要求](references/agent-contract.md)。没有明显赢家时，给几条互不支配的路线及适用条件，不得强行宣称“最佳”。

## 5. 最终交付

**写最终摘要和重排名次前，再做一次目标回查**：先不看最近消息，按原始目标独立写出当前应推荐什么；再加入补充信息，指出**哪条证据具体改变了可行性、最终效果或排名**。如果删掉最新补充后，摘要主线就完全变了，但拿不出上述影响证据，说明把局部问题误升为主线：降回适用条件、备选或附录。不能用研究篇幅、Agent 数量、引文多少证明某个局部话题最重要；用户已明确更改目标的除外。

先结论，后依据：推荐什么、为什么、**在什么条件下会改选其他路线**；每条主要路线的核心原理、优势、失败条件与关键原始资料；覆盖与未覆盖的方向、**已确认不同的机制**和**暂无法区分的候选**、独立性等级（L1／L2／L3）——不能用 Agent 数或搜索次数充当多样性；区分已实测／仅有资料／仍是假设，给出复现方法或下一个最值测试；未被采纳路线与舍弃理由，允许用户据此重开一轮。

收尾：新增机制很少、关键空白已解释、预算耗尽或用户要求停止时结束；未完成项说清楚，不无限追加搜索。

## 交付前自检

任何一条“否”就回去补：①对“原理不同”的主张有无能区分的输入？对“尚无法区分”的候选是否保留待判，而非硬合并？②每个“已核实”来源能否当场翻到那页？③有没有把常规调参写成原理改变，或把自测数字写成“已证明优于基线”？④是否分开报告确认的机制、待判候选与未覆盖方向？⑤串行模拟是否标了等级与污染路径？⑥审查是否基于冻结版本，而最终版本是否经过新测试？
