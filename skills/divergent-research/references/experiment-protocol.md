# 实验与独立评测

这份约定只在需要做真实实验、代码或硬件验证时读取。事实调研、轻量方案比较不必套用。

## 1. 先锁定比较依据

1. 保存用户原目标、必须满足的约束，以及可以推翻某个方案的反例。
2. 对现有系统复现基线：同一版代码、数据、硬件、随机种子和计算预算，记录真实原始结果。基线不能复现时先修复或说明不可比。
3. 在候选实验之前锁定指标、方向（越大越好或越小越好）、运行次数、判定误差范围、算力和时间上限。
4. 如有条件，把验证集与最终测试集分开。实验 Agent 只能根据验证集调方案；最终测试集由独立评测方保管、执行。
5. 如果是机械／硬件工程，使用没有参与设计调试的工况或样件作为保留测试；没有单独测试样件时说明原因和证据局限。

## 2. 不要让工作退化为无尽微调

- 把候选分成“稳妥、便宜、可迅速否定”和“不同原理、失败风险高、潜在收益大”两组。必要时两组同时推进；不要把绝大多数预算全耗在第一组。
- 每个实验先写要验证的假设，再记录代码版本、输入、环境、命令、耗时、资源占用、结果与失败原因。
- 若多个实验并行，避免超额申请 CPU／GPU／设备工位；跟踪排队、空闲、超时和资源冲突，停止长期无进展的任务。
- 长任务至少在每轮重要实验后（或约 60 分钟）重新判断：是否只有调参？可否从问题的物理或数学约束出发，换一种问题描述或机制？有没有此前没看过的原始研究？
- 发现结果好时，不要立即把剩余预算全部投入该路线；保留一次探索其他机制的机会。

## 3. 结果交给别人复核

- 优先让独立评测者运行**冻结**的程序与指标。实验 Agent 不得读取最终隐藏数据，更不能根据隐藏成绩继续选型。
- 审查完整实验记录、代码差异、分组和指标，重点查：只报告有利子集、使用测试集调参、修改评分办法、硬编码结果、忽略运行失败或改变时间／算力预算。
- 显示各次原始结果与波动，不只给最佳一次；把验证集分数和独立测试分数分开标注。
- 外部验证不能开展时，用“开发集结果／尚未独立验证”，不得写“已证明优于基线”。

## 4. 停止或继续

当不同机制的候选都经过最低成本的反例测试、额外实验不能带来足够新信息，或资源上限达到时停止。留下可复查的最佳方案、不同路线、失败日志和下一步最有信息量的实验。

参考：[Agent4Sci 原论文](https://arxiv.org/html/2610.28763v1) 的第 2.2—2.3 节（评测问题与隔离），第 3.3—4.2 节（Agent 行为与 Skill），附录 D（实验管理与定时检查）。
